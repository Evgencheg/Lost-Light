# Диздоки

Диздок - описание крупной фичи: что она делает, как устроена, кто за неё отвечает и как её убрать. Хранится здесь, рядом с кодом, чтобы не потеряться вместе с чьим-то аккаунтом или Discord-сообщением.

## Когда нужен

**Нужен:** новая механика, роль, антагонист, раса, режим, система, крупный порт из другого билда, переделка существующей системы.

**Не нужен:** багфикс, спрайт, текст, правка чисел, мелкий предмет. В PR пишется «мелочь, без диздока».

Сомневаетесь - считайте, что нужен.

## Как провести

1. Скопируйте [`_TEMPLATE.md`](_TEMPLATE.md) в `docs/design/<фича>.md` (латиницей, через дефис: `sec-apartments.md`).
2. Заполните всё, кроме «Задачи», статус - **Черновик**.
3. Откройте PR только с диздоком. Название: `Диздок: <фича>`.
4. Обсуждение - в PR. Одобрение кого-то из `heads` = решение принято, статус меняется на **Одобрен**, PR мёржится.
5. Диздок режется на задачи в доске GitHub Project (как - в [process.md](../process.md#4-задачи)), ссылки на них - в таблицу вверху.
6. В PR с реализацией - ссылка на диздок. Если в процессе что-то поменялось - диздок обновляется в том же PR.
7. Когда всё сделано - статус **Готов**, фича записана в [реестр](../features.md).

## Статусы

| Статус | Значит |
|---|---|
| Черновик | Пишется, обсуждается |
| Одобрен | Решение принято, можно брать задачи |
| В работе | Идёт разработка |
| Готов | В игре, есть владелец |
| На поддержке | Владелец ушёл, заместителя нет - фича работает, но никто не развивает |
| К удалению | Решено убрать - по разделу «Как выключить или удалить» |
| Заброшен | Не делается и не будет |

## Владелец и заместитель

У каждой фичи два ответственных. Владелец развивает и чинит, заместитель подхватывает, если владелец пропал. Уходите из команды - передайте свои фичи в [реестре](../features.md) и в диздоках.
