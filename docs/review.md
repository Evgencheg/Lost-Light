# Правила ревью

Что проверять в PR Lost Light. Сборка - форк [Starlight](https://github.com/ss14Starlight/space-station-14), который сам форк Space Wizards. Основной язык игры - `ru-RU`. Замечания пишем по-русски.

Процесс разработки - [process.md](process.md), лицензии источников - [LEGAL.md](../LEGAL.md), карты - [mapping-checklist.md](mapping-checklist.md).

## Как ревьюить

- Смотри только то, что PR изменил. Старый код не трогай, если PR его не менял и не копировал оттуда паттерн.
- Не требуй правок стиля в нетронутом коде и переделок «на вкус».
- Одно конкретное замечание с предложенным исправлением лучше общего совета.
- Не проси диздок и запись в `docs/features.md` для мелочей: баги, тексты, спрайты, числа, мелкие предметы, мелкие порты.
- Каждое замечание подкрепляй строкой из diff.

## Приоритеты

От блокирующего к мелочам:

1. Правки в `RobustToolbox/**` (движок) и изменение сабмодуля `RobustToolbox`.
2. Секреты: токены, пароли, API-ключи, вебхуки, строки подключения, приватные адреса.
3. Размещение и пометки `LP edit`.
4. Ошибки предсказания и сети, утечки скрытых данных, нет серверной проверки ввода клиента.
5. Текст для игрока без локализации.
6. Дублирование существующих механик, хардкод.
7. Нет проверки для рискованных изменений.
8. В PR смешаны несвязанные темы.

## Блокирующее

- **Движок.** `RobustToolbox/**` не правится, сабмодуль в PR меняться не должен.
- **Секреты.** Значения - только через CVar с пустым дефолтом и закрытый конфиг; в примерах заглушки вроде `<token>`.
- **Дефолты CVar в коде** (`CVarDef.Create`) не меняются. Другое значение - в пресете `Resources/ConfigPresets/_LP/LP.toml` или в закрытом конфиге.
- **Апстримные таблицы БД** не меняются. Для нашего - свои таблицы; миграции нужны и для SQLite, и для Postgres.

## Размещение

- Новый код и ресурсы - в папках `_LP`: `Content.{Shared,Server,Client}/_LP/<Подсистема>/`, `Resources/Prototypes/_LP/`, `Resources/Textures/_LP/`, `Resources/Audio/_LP/`, `Resources/ServerInfo/_LP/`. Внутри `_LP` структура повторяет апстрим (`Components`, `EntitySystems`, `UI` ...).
- Namespace совпадает с путём папки. ID наших прототипов - с префиксом `LP`.
- Код порта - в папке namespace источника (`_Funkystation`, `_Goobstation`, `_Corvax` ...), не в `_LP`, даже если сильно переделан.
- CVar-ы - `CVarDef<T>` в `Content.Shared/_LP/CCVar/`.

## Пометки в чужих файлах

Любая наша правка файла вне `_LP` помечается:

| Язык | Одна строка | Блок |
|---|---|---|
| C# | `// LP edit` в конце строки | `// LP edit start` / `// LP edit end` |
| YAML | `# LP edit` в конце строки | `# LP edit start` / `# LP edit end` |
| XAML | `<!-- LP edit -->` | `<!-- LP edit start -->` / `<!-- LP edit end -->` |

- Правка больше одной строки - только блоком `start` / `end`.
- Пометка голая. Пояснение (`// LP edit start - зачем`) - только если причина неочевидна из кода; пояснение того, что и так видно («добавлен компонент X»), - замечание.
- Блок узкий: без постороннего форматирования и перестановок. Рядом уже есть наш блок - его расширяют, а не ставят второй.
- Удалённый чужой код - строка на его месте: `// LP edit - убрано ...` / `# LP edit - убрано ...`.
- В YAML-списке пометка - только комментарием. `- # LP edit` создаёт пустой элемент списка и ломает прототип.
- Не помечаются: файлы `.ftl`, директивы `using`, всё в папке `_Corvax`, перевод существующих страниц гайдбука. Наш новый контент в чужой странице гайдбука помечается.
- Чужие пометки (`Starlight`, `NullLink`, `DEN edit`, `Corvax` ...) не трогаются. Правки, пришедшие с портом, сохраняют пометку источника; `LP edit` - только на наши собственные правки.
- Наш код в чужой C#-системе - partial-класс в `_LP`, в чужом файле - максимум одна помеченная строка-вызов. Члены, всё же добавленные в чужой класс, - в `#region LP` ... `#endregion`.
- Смена семантики чужого компонента, порядка enum или списков, формы сериализации, сетевого состояния - только с обоснованием в PR.

## Partial-прототипы

- Чужой прототип под наш контент меняется через partial в `Resources/Prototypes/_LP/Partials/<Тема>/<тема>.yml` (файлы по темам, не по пути оригинала), а не правкой файла.
- У partial обязателен `type: !PartialOnly ...`: без него опечатка в ID создаёт новый прототип.
- У `!type:CreateVariants` список `values` лежит внутри `id`, а не рядом. `localizedDataset` через `CreateVariants` не сливается. `!PartialModified` не используется.
- Через partial нельзя: менять `parent` (теряются остальные родители), удалять элемент-маппинг списка (`- map: [...]`, `- !type:...`), надёжно удалять через `!CombineIndex`. В этих случаях - правка файла с `LP edit`.
- Убрать прототип - через `Resources/IgnoredPrototypes/` (работает на весь файл), а не удалением файла.
- Для портов partial не делается: правки чужих прототипов под порт вносятся в файл.
- Правка касается `parent`, станций, карт или базовых прототипов - в PR должно быть сказано, что прогнаны интеграционные тесты или MapRenderer: YAML-линтер потерю наследования не ловит.

## Код

- Компонент - только данные, логика в системе. Схема `On...` (тонкий обработчик) → `Try...` (публичное действие с проверками) → `Can...` (только проверки, ничего не меняет) → `Do...`.
- Подписки на события - атрибутом `[SubscribeLocalEvent]` на методе-обработчике, без лямбд.
- Зависимости - `[Dependency] private XSystem _x = default!;` без `readonly`: иначе предупреждение RA0051.
- Без хардкода: `ProtoId<T>` / `EntProtoId`, `LocId`, `SoundSpecifier`, `SpriteSpecifier`, `[DataField]`, CVar. Нет ветвлений по ID прототипа.
- Не дублируется существующая механика; нет кода «на всякий случай», «временного» кода, рефлексии, статического глобального состояния.
- Без очевидных комментариев; комментарий объясняет «почему». XML-доки - на публичные API и неочевидные `DataField`.
- Логика не впихнута в одну строку ради короткого diff.
- Новых предупреждений компилятора в изменённых файлах нет.

## Предсказание, сеть, безопасность

- Новый интерактивный геймплей - предсказываемый, в Shared. Если нет - в PR указана причина.
- `[NetworkedComponent]` - только в Shared. Сетевые поля - `[AutoNetworkedField]` и `Dirty` после изменения; не `Dirty` каждый тик.
- В предсказываемом коде нет `PopupEntity`, `PlayPvs`, голого `IRobustRandom`, обычного `Spawn` / `Del`: нужны `PopupPredicted` / `PopupClient`, `PlayPredicted`, `PredictedSpawn*`, `PredictedDel`.
- Всё, что пришло от клиента, проверяется на сервере: сессия, права, дальность, кулдауны, состояние цели. Каждое сообщение BUI валидируется на сервере.
- Скрытые данные (антагонист, цели, тайники, админское) не сетятся всем, только владельцу или конкретной сессии. PVS-оверрайды - редко и с объяснением.
- Плейтайм меняется только через `PlayTimeTrackingManager`: прямой `UpdatePlayTimes` ломает синхронизацию NullLink.

## Локализация

- Ни одного текста для игрока в C# и XAML: в C# - `Loc.GetString`, в XAML - `{Loc '...'}`. Фразы не собираются конкатенацией.
- Ключи - kebab-case с префиксом подсистемы, не общие вроде `error-message`.
- Наши ftl - только в `Resources/Locale/ru-RU/_LP/`, `en-US/_LP` не заводится. ru-файл вне `_LP` без пары в en-US скрипт локализации удалит.
- `name` / `description` прототипов в YAML - по-английски; русский - в `Resources/Locale/ru-RU/ss14-ru/prototypes/`, ключи `ent-` - только там.
- ftl порта - пара `en-US/_<Namespace>/` и `ru-RU/_<Namespace>/`. Исключение - папки из `ignored_paths` в `Tools/localize/localize_config.yml` (`_LP`, `_corvax`, `_Orion`): там сразу ru-RU.
- В переводе сохранены переменные, функции, разметка и селекторы; набор переменных как в en-US. Нет частичных переводов (английские куски в русской строке).
- Термины - как в уже переведённом: НаноТрейзен, СБ, ГСБ, МТГ, СРП, «заболтировать / разболтировать». Имена сущностей - с маленькой буквы.
- Изменилось поведение для игрока - в том же PR обновлены гайдбук и ftl.

## Прототипы и ресурсы

- Порядок полей прототипа: `type`, `abstract`, `parent`, `id`, `categories`, `name`, `suffix`, `description`, `components`. Элементы `components:` без доп. отступа и многострочно.
- YAML - только пробелы, 2 на уровень.
- У каждого RSI в `meta.json` есть `license` и `copyright` (автор и источник); `delays` - отдельный список на каждое направление. У звуков - `attributions.yml`, одна запись на файл.
- Ассет без лицензии и источника, All Rights Reserved или «из интернета» не принимается. CC BY-NC - только с отметкой в `LEGAL.md`.
- Новый источник порта - строка в `LEGAL.md` в том же PR. SPDX-заголовки источника не переносятся. Заголовок MPL не удаляется.
- В папках `_*`: без пробелов в конце строк (кроме `.ftl`), с переводом строки в конце файла, без BOM, `meta.json` с отступом 4.

## Состав и описание PR

- Один PR - одна тема. Несвязанные изменения (разные баги, фича вместе с клинапом или рефакторингом чужого кода, порт вместе с правками другого контента) - отметить и предложить вынести в отдельный PR. Исключения: вливание апстрима, массовые переводы, сборник мелких фиксов, если это прямо сказано в описании.
- Описание по шаблону: «мелочь, без диздока» или ссылка на диздок; issue - строкой `Fixes #N`; шаги проверки для каждого изменения. Непроверенное так и помечено; не заявлены проверки, которых не было.
- Заметное игрокам изменение - блок `:cl:` в «Списке изменений».
- Крупная фича - диздок `docs/design/<фича>.md` и запись в `docs/features.md` в том же PR.
- Баг в коде Starlight у нас не правится: фикс отправляется в Starlight, у нас ждём вливания. Переводы ru-RU строк Starlight правятся у нас.
